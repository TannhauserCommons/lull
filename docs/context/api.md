# API contract

Between `web/` and the server, and between crates (events). It's derived from `design/DESIGN.md` §8 and the shapes in `design/prototype/mock-data.js`, which is the canonical example of every object the UI reads.
- Backend owners keep their own section true and edit only that section.
- The web session builds against this page.
- A shape change is made here in the same commit as the code.

## Conventions

- **Paths and auth.** JSON, everything under `/api` (Subsonic under `/rest`), same origin as the UI. Every call needs a paired device's token (ADR-0002, see Hub) except the few the Hub section marks open.
- **Field names.** camelCase in JSON. Ids are strings:
  - `t-…` track, `al-…` album, `ar-…` artist, from `lull_core::ids`: one id per song, whatever its source;
  - `pl-…` playlist, `job-…` job;
  - a tag's id is its name.
- **Errors** are `{ "error": kind, "message": text }`, where `message` is a sentence the UI can show as is:
  - 400 `bad_request`;
  - 401 `unauthorized`;
  - 404 `not_found`;
  - 409 `conflict`;
  - 429 `too_many_requests` (a limit lull keeps on purpose; the message says when to retry);
  - 502 `upstream` (a dependency answered badly);
  - 503 `unavailable` (a dependency is down or not configured);
  - 500 `internal`.
- **Entities.** Any response that names tracks, albums or artists also carries them as `"entities": { tracks: {id: Track}, albums: {id: Album}, artists: {id: Artist} }` (`lull_core::model::Entities`), so the UI's lookup cache (`M.track(id)`...) can resolve every id it's given.
  - A **Track** is the mock track without `sources`, `plays` and `liked`:
    - from the mock: `id, title, artistId, artist, albumId, album, year, no, disc, duration, tags, saved`;
    - file facts flattened in: `format, codec, lossless, khz, bits, kbps, sizeBytes`.
  - An **Album** or **Artist** is the mock shape (see `lull_core::model`).
- **Per-user state** comes from collection endpoints and is never inlined in entities: liked, followed, plays.
- **Lists** take `?limit=&offset=` and return `{ items, total, entities }`.
- **Revalidation.** Any answer with an `ETag` (covers, the UI's files) answers a matching `If-None-Match` with a bodyless 304.
- **Compression.** Text answers over 1 KB come brotli- or gzip-compressed when the request's `Accept-Encoding` allows (browsers always do); audio, pictures and `/api/events` never are (hub.md#files).
- **Time.** Durations are in seconds. Timestamps are unix seconds (`at`), and the UI formats them.

## Hub (`crates/server`, `lull_core::{devices, settings}`)

ADR-0002; how it works: [hub.md](hub.md). A device token travels as the HttpOnly cookie `lull_device` (browsers, set by the hub; the app's webview may carry it too) or `Authorization: Bearer <token>` (the app). Everything under `/api` needs it except `GET /api/setup`, `POST /api/setup/claim` and `POST /api/pair`; everything outside `/api` is open (the static UI, `/health`, and `/rest`, which checks Subsonic app passwords itself). Loopback gets no exemption. A Subsonic app password is refused under `/api`.

**Codes** are typed by people: case, spaces and dashes don't matter. After 10 wrong codes in a minute, every code is refused (401) for the rest of that minute.

| Method + path | Returns |
|---|---|
| `GET /health` (open) | `{ version, build, services: { soulseek, library, lastfm, cache: { state: ok\|warn\|down\|off, detail, extra } }, flags: [name] }`. `flags`: the switches `LULL_FLAGS` turns on (ADR-0096), usually none. `version` is `0.2.4` for a release and `0.2.4+12.abc1234` for a build with changes on top; `build` is `{ release, changes, commit, install: desktop\|docker\|server }` (`lull_core::build`). Always 200 while serving |
| `GET /api/updates[?check=true]` | `{ version, build, latest: { version, url, publishedAt } \| null, state: current\|available\|ahead\|unknown, checkedAt, error }`: this build against lull's newest release on GitHub (not drafts or pre-releases). `ahead`: everything in the newest release and changes since (an install that follows main). Asked only when called, kept 6 hours; `check=true` asks again, at most once a minute. With the `hub-self-update` switch on, also `selfUpdate: { can, why, step, error, failed }`: whether Update can be pressed, why not (a plain sentence, when a newer release is out), what a running update is doing, why the last one stopped, and a version that didn't start (`{ version, why, at }`) |
| `POST /api/updates/apply` (`hub-self-update` switch, ADR-0090) | 202 and the `/api/updates` body: starts updating to the newest release, a hub installed as the Linux package or the image only. 409 with the reason (`selfUpdate.why`) when it can't, or while an update runs; 404 with the switch off. `GET /api/updates` follows it (`selfUpdate.step`); the hub then restarts on the new version. Also over the admin socket (`lull update`) |
| `GET /api/ping` | 204, or 401 without a valid device token (the UI then shows pairing). A cookie-carried token gets its cookie renewed (browsers cap a cookie at 400 days) |
| `GET /api/events` | Server-sent events, one per bus event: `event: <topic>`, `data: <json>`. `resync` means the client missed events and refetches what it shows. The connection marks its device online (lull Connect). It ends when the hub restarts its crates (after `hub.restarting`; reconnect) or when its device is unpaired |
| `GET /api/setup` (open) | `{ claimed: bool, soulseekManaged: bool, steps: { library: bool, soulseek: bool, lastfm: bool } }`. `claimed`: a browser or app is paired. A step is `true` when done: that service reports `ok` or `warn` in `/health`; `false` means first run still needs it. `soulseekManaged`: lull runs this slskd (`LULL_SLSKD_CONFIG_FILE`, the desktop app), so the Soulseek account is set in lull with `LULL_SOULSEEK_USERNAME` and `LULL_SOULSEEK_PASSWORD`; otherwise it is configured where slskd runs, and setup shows slskd's connection state |
| `GET /api/host` (admin socket only, ADR-0090) | `{ version, port, dataDir, lan, publicUrl, paired }` for lull's commands. Over the admin socket (`<data>/admin.sock`) these routes need no token: `GET /api/setup`, `GET`/`PATCH /api/config`, `GET`/`PUT /api/library/source`, `POST /api/pair/codes`, `GET /api/host`; every other route still does. Over TCP `/api/host` is 404 |
| `POST /api/setup/claim { code, name, kind?: browser\|app }` (open) | The first device, with the setup code (printed in the hub's log while no browser or app is paired, or `LULL_SETUP_CODE`). Answers like `POST /api/pair`; 401 for a wrong code or once a device is paired |
| `POST /api/pair/codes` | `{ code, url, expiresAt }`: a single-use 6-character pair code, valid 10 minutes; `url` is `<hub url>/#/pair/<code>` for the QR, from `LULL_PUBLIC_URL` or else the address the asking device used |
| `POST /api/pair { code, name, kind?: browser\|app }` (open) | 200 `{ device }` plus the cookie for a browser (the default kind), `{ device, token }` for an app; 401 for a wrong, used or expired code; 400 without a name |
| `GET /api/devices` | `{ items: [Device + { online, state? }], me }`. Device `{ id, name, kind: browser\|app\|subsonic, createdAt, lastSeen, private }`; `state` is the last `device.state` of an online device |
| `PATCH /api/devices/{id} { name?, private? }` / `DELETE /api/devices/{id}` | 204: rename and/or switch **private listening** (kept per device on the hub, so it survives reloads) / unpair (its token stops working and its event streams end at once; unpairing the last browser or app arms a new setup code). `{id}` may be `me`, the calling device: `PATCH /api/devices/me { "private": true }` is how a device switches itself. 400 with neither field, 404 for an unknown id. See [collection.md](collection.md#private-listening) |
| `POST /api/devices/subsonic { name }` | `{ device, username: "lull", password }`: an app password for a Subsonic client, shown once |
| `POST /api/devices/me/state { trackId: string\|null, position, playing, volume, queue: [trackId], queueIndex: int\|null }` | 204; republished as `device.state`. `position` in seconds, `volume` 0-1 |
| `POST /api/devices/{id}/command { action: play\|pause\|seek\|next\|prev\|volume\|takeover\|enqueue, value?, tracks? }` | 204; forwarded as `device.command`. `seek` (seconds) and `volume` need `value`. `enqueue` needs `tracks` (1 to 500 song ids), which no other action takes: the device adds them to next up without interrupting (a share page's Add to queue). 409 when that device has no open event stream. `takeover`: the target sends its state to the caller and pauses |
| `PUT /api/pictures/screen { gen, visible: [[pic, size]], near: [[pic, size]] }` | 204. What this device shows now, top to bottom (ADR-0033): `pic` is a picture's route and id as its URL names it (`catalog/art/al-…`, `catalog/art/ar-…`, `art/al-…`; no `api/`, no query), `size` the served size it is drawn at, or 0 for an artist drawn without a photo (one is looked for). `near`: within about a screen of view. `gen` grows with each report from the device; an older one is ignored. The hub fetches outside pictures in this order: what plays, then visible, then near, then what a request waits for, newest screen first; work no screen shows any more is dropped before it starts, and what comes onto a screen and isn't cached is fetched without a request. At most 400 pictures; 400 for a picture or size lull doesn't serve. A screen counts for 10 minutes after its last report |
| `GET /api/config` | `{ items: [{ key, value, set, source: env\|stored\|default, secret, restart }] }`, one per key the app can set (`lull_core::settings::KEYS`). `value` is `null` when unset and always for a secret; `set` says whether it has a value. `env` keys are locked. `restart` is `true` for every key: the crates read them all at start. With the `secrets` switch on (ADR-0091), each secret also has `kept: { in: keyring\|file\|env\|config-file\|database, text, problem? }`: where it is, as Settings says it under the field, and why it can't be read now (a locked keyring) or isn't safe there (a `LULL_CONFIG` file every user can read); and the body has `credentials: { in: keyring\|file, text, problem, offer }`: where new ones go, why that vault won't work now, and the other vault the listener can choose |
| `PUT /api/credentials { keep: file\|keyring }` (`secrets` switch) | The listener's choice of vault (ADR-0091): lull's own file instead of a keyring that won't open, or the keyring again. The crates restart and move what they can read; what a locked keyring holds is typed again. 404 with the switch off |
| `PATCH /api/config { LULL_X: value\|null }` | 200 `{ items }`. `null` or `""` goes back to the default. The whole merged configuration is checked with `Config::from_vars` before anything is stored; a 400 names the key (unknown, environment-only, set in the environment, or invalid). `LULL_LIBRARY` is refused: switch with `PUT /api/library/source`, which reconciles the library first. `LULL_SOULSEEK_USERNAME` and `LULL_SOULSEEK_PASSWORD` (set together) are refused unless `soulseekManaged`: "Soulseek is configured where slskd runs". After the restart, lull writes the account into slskd's config file, waits for slskd to reload it and logs in again (`DELETE`, then `PUT /api/v0/server`); the `soulseek` service shows the result. Then the hub restarts its crates (`hub.restart`) |

## Events

Topic → payload. Published on the bus and streamed to the browser. Owners add their topics here.

| Topic | Publisher | Payload |
|---|---|---|
| `service` | any (via `ctx.status`) | `{ name, service: { state, detail, extra } }` |
| `search.results` | soulseek | `{ searchId, query, files, peers, done, results?, entities?, onlySoulseek?, error? }`. While the search runs only the counters move (`done: false`); the last event (`done: true`) carries `results` and `entities`, or `error`. `onlySoulseek` is `null` until discovery's `search.catalog` for the query has arrived, then the result songs no catalog listed; a catalog arriving after the results publishes the last event again with it. Rows in the Soulseek section |
| `transfer` | soulseek | `{ jobId, trackId, peer, state: queued\|transferring\|stalled\|done\|failed\|cancelled, queuePos, received, size, speed, error }`. Bytes, bytes/s; `peer` changes on fallback. Absent values are `null` |
| `stream` | soulseek | `{ trackId, jobId, status: finding\|choose\|queued\|buffering\|streaming\|stalled\|fallback\|failed, peer, format, peersFound, queuePos, received, ranges, size, speed, attempt, failedPeers: [{ peer, at }], error, belowMinimum, seekAheadS, youtube, unverified, unplayable, choices?, upgrade? }` drives the player's streaming states, while the track streams. Every opening of `GET /api/stream/{trackId}` sends one with where the song stands now (also for a finished or cached copy), so the player knows how far it may seek. `youtube`: the copy is YouTube's (`peer` is `YouTube`, `format` its own chip such as `YouTube · Opus 160`; never below the minimum). `unverified`: that YouTube copy's sound couldn't be checked against any reference (youtube.md#sound-checks): the player asks "Right song?" (`POST /api/tracks/{id}/verify`). `at` is the percent reached. `ranges`: what has arrived, as `[[from, to], ...]` fractions of the file (a copy arrives in legs from where the listener seeks, so it may have gaps; `received` is their sum in bytes). `seekAheadS`: a seek past what has arrived makes the hub start the transfer there when the transfer running would take longer than this many seconds to get there (streaming.md#legs); `null` while it can't. `speed`: bytes a second, how fast it arrives now (the player's "Waiting for 2:40, about 8 s" and the source card's rate). `attempt` goes up on each fallback: reopen the stream URL (the old response ends) and seek back by time; the first event after opening only tells which attempt that response is. `belowMinimum`: the copy playing doesn't pass the streaming minimum (`playBest`, or the listener's pick): show a badge. `choose` (streaming `below: ask`): no copy passes; `choices` lists up to 8 Sources found; answer by opening the stream with one's `peer` + `path`, or skip. `upgrade { peer, path, format, status, received, size, ready }`: a better copy on its way beside the lesser one playing, which the player may switch to (`sources.switchToBetter` on, a copy nobody picked); `ready` once all of it is here or it arrives 1.5 times faster than it plays ([streaming.md](streaming.md#better-copies)) |
| `save` | library | `{ jobId, trackId, step: 1-5, status: running\|done\|failed\|pending\|waiting\|cancelled, pct, error, kind: transfer\|match\|write\|null, nocover, upgrade, belowMinimum }` (steps: transfer, match, cover, tag+write, rescan). `kind` names the recovery for a failure; `pct` moves during step 1 only. `waiting` (saving `below: wait`): no copy passes the saving minimum yet; `error` says so and the job searches again by itself. `upgrade`: started by auto-upgrade. `belowMinimum`: the copy saved doesn't pass the saving minimum (auto-upgrade watches it). `cancelled`: `DELETE /api/saves/{jobId}`; the job is gone after this event |
| `job` | any | `{ jobId, kind: transfer\|save\|import\|rescan, started, ... }`: one Activity row, the same shape `GET /api/jobs` lists. Library's rows: save `{ trackId, step, stepState, pct, error, failKind, nocover }`, rescan `{ state: running\|done\|failed, pct, detail }`. Other crates publish their own rows here to appear in `/api/jobs` |
| `saves.request` | collection | `{ trackIds }`: songs to save as `POST /api/saves` saves them (the saving profile picks), for a link import with "Save the songs too", a song liked on its own with `library.autoSaveLikes` on, and `POST /api/likes/save`; library queues them, skipping saved songs and keeping running jobs |
| `outside` | collection | `{ id, songs: [{ pos, status: matched\|unmatched, trackId }], entities, done }`: an outside playlist's songs matched in the background after `GET /api/outside` (a batch a second, `done` on the last) |
| `bookmark` | collection | `{ id, saved }`: an outside playlist bookmarked or removed (another device's Library follows) |
| `play.started` | collection | `{ playId, trackId, at, duration, artist, title, album }`. lastfm now-playing, taste. The `plays` row is written first. Never for a device in private listening |
| `play.ended` | collection | `{ playId, trackId, at, playedS, completed, skipped, duration, artist, title, album }`, exactly once per play. `at` is the play's **start** (Last.fm's timestamp). Scrobbling, taste. Never for a device in private listening |
| `playlist` | collection | `{ playlistId, deleted }`: once per playlist create, rename or description change, track change and delete, from the routes, the `Collection` seam and `/api/sync` alike (a deleted playlist has `deleted: true`). Library mirrors playlists into Jellyfin from it; other devices refetch |
| `like` | collection | `{ trackId, liked }`. Taste, other devices |
| `follow` | collection | `{ kind: artist\|tag, id, followed }`. Discovery, other devices |
| `settings` | collection | The stored settings (the editable part of `GET /api/settings`), at start-up and on every change. Collection starts after every other crate, so a receiver made in `start()` gets the start-up copy |
| `scrobble` | lastfm | `{ playId (string), status: pending\|done\|short }`: queued, sent to Last.fm, or short of Last.fm's rule (History's scrobble column). Nothing while Last.fm is off, disconnected or scrobbling is switched off |
| `lastfm.history` | lastfm | `{ user, artists: [{ name, plays }] }`: the listener's Last.fm top artists, a taste signal for discovery; empty when off or disconnected |
| `hub.restart` | any | `{ reason }`: asks the hub to restart its crates with the current settings (a setting changed). The hub publishes `hub.restarting` and the UI reconnects. Requests made while one waits are covered by it |
| `hub.restarting` | hub | `{ reason }`: the hub's crates are restarting. Every SSE stream ends right after it; requests meanwhile wait for the new crates (about a second) |
| `device.state` | hub | `{ deviceId, trackId, position, playing, volume, queue, queueIndex, at }` |
| `device.command` | hub | `{ deviceId, action, value, from }`: only the device named acts on it |
| `device.online` | hub | `{ deviceId, online }`: the device's first event stream opened, or its last one closed (or it was unpaired) |
| `theme.changed` | themes | `{ id }`: a stored theme's files changed; devices using it reload its CSS |
| `pack.changed` | themes | `{ id }`: a stored standalone pack's files changed (a theme's pack changing fires `theme.changed`); devices using it refetch `GET /api/packs` |
| `skins.mine` | skins | `{}`: Your skins are something else now (a skin added or deleted, a change in a folder, a rescan); refetch `GET /api/skins/mine` |
| `library.source` | library | `{ mode: folder\|jellyfin, state: switching\|done\|failed, detail }`: a switch of the library source (`mode` is the target). `done` is followed by `hub.restart` |
| `search.more` | discovery | `{ query, artists, albums, tracks, playlists, errors?, entities, done }`: catalog additions for a running `/api/search` query (only ids not shown yet, best first), appended by the UI without reordering shown rows. `entities` also refreshes shown rows that gained facts (art, length); `errors` is every failed source so far; `done: true` on the last |
| `feed.avail` | discovery | `{ trackId, avail: [soulseek\|youtube], noSource }`: where one of the feed's picks can play from, as the checks after a build answer (discovery.md#where-a-pick-plays) |
| `feed.updated` | discovery | `{ updated }`: the feed changed (rebuilt, or new releases re-served as Soulseek's answers arrived); refetch `GET /api/feed` |
| `album.updated` | discovery | `{ albumId }`: the tracklist an album page answered `partial: true` without has arrived (cached) or failed, within 90 s; refetch `GET /api/albums/{id}` |
| `artist.updated` | discovery | `{ artistId }`: every section an artist page named in `pending` has arrived (cached) or failed, within 90 s; refetch `GET /api/artists/{id}` |
| `search.catalog` | discovery | `{ query, trackIds }`: the query's 50 best catalog tracks, once every source is in (again when the same words are searched while the run is kept). Soulseek pre-warms their sources (paced) and uses them to tell which Soulseek songs no catalog knew |
| `art.ready` | core (`lull_core::pictures`) | `{ keys: [albumId \| artistId], images?: { artistId: url } }`: pictures the hub fetched and now has (at the size a page asked for or a larger one, or ahead of it), batched over 250 ms. A page that got 404 "not yet" for one asks again then, never on a timer. `images`: an artist's newly vetted photo (`api/catalog/art/<id>?v=…`), the entity's new `image`, so a page that drew the artist without one shows it without reading anything again |
| `catalog.tracks` | discovery | `{ entities }`: bare songs the UI asked about (`POST /api/catalog/resolve`), now resolved: each under its own id, with the catalog's title, artist and album, and that album pictured. The UI absorbs them and repaints covers (discovery.md#bare-songs) |

## Soulseek (`crates/soulseek`)

| Method + path | Returns |
|---|---|
| `GET /api/soulseek/search?q=` (ADR-0008: moves here from `/api/search`, which becomes discovery's catalog search) | `{ searchId, soulseek, entities }`. Answers as `search.results` events with that `searchId`, as before: live `files` / `peers` counters for up to 15 s, then the results, or `error` when slskd lost them. The same words again within 10 minutes reuse a search that is running or ended with results; an empty or failed one runs again. Queries under 3 characters don't search. Results also carry `onlySoulseek: [trackId]`, the songs no catalog knew (built from file tags), once discovery's `search.catalog` for the same query has arrived |
| `search.results` rows | `{ kind: "track", trackId, sources, best: Source, dup? }`: one song merged across peers; `sources` = how many peers; `dup` is `note` (already saved) or `better` (this file beats the saved one by `Quality::beats`). `{ kind: "album", albumId, trackIds, folders: [{ peer, path, format, tracks, sizeBytes, speed, freeSlot, queue, score, cover }] }`: a peer folder holding 3+ songs, the same album on several peers listed best first. Songs first by peers sharing them, then by score; at most 200 songs and 40 albums |
| `POST /api/tracks/{id}/verify { answer: yes\|no }` | 204. "Right song?" for the YouTube copy of the song playing unverified (youtube.md#sound-checks): yes makes it the song's reference; no refuses it for the song and drops it from the cache, so the next opening of the song takes the next copy. 409 when no YouTube copy of the song is playing, 400 for another answer |
| `GET /api/tracks/{id}/sources[?for=save]` | `{ sources: [Source], youtube: { peer: "YouTube", path, sizeBytes, format, official, section } \| null, done, why }`. `why`: the hub's sentence when the search ended with no copy at all ("No Soulseek peer shares this song right now."), else null; the web words no such fact of its own. `sources` holds every peer's copy of the song, whatever folder or album it is in (soulseek.md#source-rules), in the order the streaming profile (or with `for=save`, the saving one) takes them: copies that pass its minimum by its `pick`, then the rest, then peers with too long a queue. A Source is `{ peer, path, format, sizeBytes, speed (MB/s), speedMeasured, measuredAt, expectedSpeed (MB/s), freeSlot, queue, score 0-100, factors: { format, speed, slot, queue, stalled }, preferred, stalledBefore, meets, queueTooLong, aboveMax }`: the factors add up to the score, `stalled` is 0 or a negative penalty; `speed` is what lull measured from the peer (`speedMeasured`, last at `measuredAt`, unix seconds), else the peer's own figure; `expectedSpeed` is what ranking expects (ADR-0015, soulseek.md#ranking); `meets` = passes the profile's minimum; `queueTooLong` = busy with more people waiting than `maxPeerQueue` (never picked automatically); `aboveMax` = above the streaming cap `sources.stream.maxKbps` (lossless counts as above any cap), taken only after the copies within it (always false with `for=save`). When no search for the song itself ran in the last 6 hours (copies other searches came across don't count) this starts one and answers `done: false`: ask again every couple of seconds until `done`. `youtube` is the song's YouTube copy while Settings › Sources › YouTube is on (never with `for=save`): the copy the player's YouTube path plays, its `format` the chip ("YouTube · Opus 160"), lossy, with no score and never below the minimum; `section` is `[from, to]` in seconds when the copy is a song cut from a full-album upload (youtube.md#full-album-uploads), else null; `null` while YouTube is off or nothing matches, and `done: false` while the match is being made. `GET /api/tracks/{id}/stream?peer=YouTube&path=` plays it. 404 for a track id lull never handed out |
| `GET /api/stream/{trackId}[?peer=&path=]` | Audio with Range support (200 whole, 206 one range). Starts the transfer if needed (searching for the song first when no source is known) and serves bytes as they arrive, from copies in the streaming profile's order; `peer` + `path` (a Source's) plays that source. With another copy than the one playing, it replaces the transfer (switching source mid-song, or answering `choose`): the old one is cancelled unless a save needs it, and its response ends; seek back by time. The answer waits for the first bytes; a range beyond what has arrived waits for its bytes as long as the transfer runs, and only a range past the end of the file is 416. A stall falls back to the next copy and ends the response (`stream` events). 502 when no peer delivers. Saved tracks are streamed by library, not here |
| `GET /api/stream/{trackId}/copy?peer=&path=` | One copy's bytes (Range as above) while it plays or arrives beside the copy playing, changing nothing: the player lines a better copy up before switching. 404 when no fetch holds that copy |
| `POST /api/stream/{trackId}/output-error { jobId? }` | The player's audio failed while it followed that job (streaming.md#a-songs-outcome): the job's `stream` event shape answers. A failed job answers as it is; one whose copy arrived records `unplayable` ("this copy can't be played in <device> (<format>)", the calling device's name) on the job and answers that. Without `jobId`: the song's live job, else its latest. 404 for a job the hub no longer knows. Never starts or restarts a transfer |
| `POST /api/stream/{trackId}/switch { peer, path }` | 204: the better copy on its way becomes the song's stream (later `stream` events are its own, with its own `jobId` and `attempt`); the copy before it stops once its response ends, unless a save needs it. 409 when that copy is no longer on its way ([streaming.md](streaming.md#better-copies)) |
| `DELETE /api/stream/{trackId}` | 204. Stop: cancels the transfer (skip / next) unless a save needs it or a device lists it to preload; slskd keeps the partial file, so playing it again resumes |
| `PUT /api/stream/prefetch { tracks: [trackId] }` | 204. The songs queued after the current one, in order, at most 3 (`playback.prefetchCount`); replaces the calling device's list, `[]` clears it. Each listed song that isn't saved, cached or already fetching is fetched in order, behind the playing song, with no `stream` events; a song no device lists any more is cancelled 10 s later unless it is playing or saving. `GET /api/stream/{trackId}` joins a running preload (one `stream` event says where it stands) or plays a finished one from the cache at once. Unknown ids are skipped. 400 for more than 3 tracks or another shape (streaming.md#preloading) |

## App releases (`latest.json`)

Not the hub's: the apps read `https://github.com/TannhauserCommons/lull/releases/latest/download/latest.json` (`plugins.updater.endpoints` in `app/tauri.conf.json`), which the release job in `.github/workflows/app.yml` writes for each `v*` tag. Tauri's static format plus one field of lull's: `{ version, pub_date, platforms: { <platform>: { url, signature } }, android: { url } }`, where the platforms are `windows-x86_64` and `windows-aarch64` (the NSIS installer), and `linux-x86_64` and `linux-aarch64` (the AppImage) each with `-deb` and `-rpm`. Each bundle job writes its own entries and the release job merges them (`scripts/updater-manifest.mjs`, which refuses a release missing any of them). The desktop updater ignores `android`; Android reads only `version` and `android.url` (android.md, Updates). Each app finds its own build: Tauri looks up `<os>-<arch>-<deb|rpm>` when it was installed from that package, else `<os>-<arch>`.

## Themes (`crates/themes`)

ADR-0004; format, hooks and slots: [themes.md](../themes.md). Built-in designs are static files of the UI (`/designs/<id>/`); these endpoints serve the listener's themes, stored in `<data_dir>/themes/<id>/`. A built-in id in a path is a 404.

| Method + path | Returns |
|---|---|
| `GET /api/themes` | `{ items: [{ id, name, author, api, extends, shell, swatches, modes, description, preview, slots, coverVariety, builtIn, pack }] }`: the five designs, then the listener's themes (a folder whose `theme.json` no longer reads is left out and logged), each with `rev` (16 hex: its files now and this lull's version) and `pictures` (the modes lull has a picture of for that `rev`, ADR-0080). `pack`: the theme carries a sound and easter-egg pack (always `false` for a built-in design, whose pack is `/packs/<id>/`) |
| `GET /api/themes/{id}/{path}` | A file of a stored theme (`theme.json`, `theme.css`, `slots/*.html`, `assets/*`, and its pack's `pack.json`, `pack.css`, `sounds/*.ogg` as `audio/ogg`), ETag'd, `no-cache`, served under a sandboxing CSP |
| `POST /api/themes[?replace=true]` (body: a `.lulltheme` zip, up to 16 MB) | 200 manifest (with `builtIn: false`, `rev` and `pictures`): stored under the id its `theme.json` names. 409 when that id exists, unless `replace` |
| `PUT /api/themes/{id}` (body: a `.lulltheme`) or `PUT /api/themes/{id}/{path}` (one file, from Theme Studio) | 200 manifest. A new theme starts with its `theme.json` (it gets an empty `theme.css`). ### Sound and easter-egg packs

ADR-0081. A pack is a `pack.json` (`id`, `name`, `author`, `api`, `description`, `sounds`, `eggs`), Ogg Opus or Vorbis files in `sounds/`, an optional `pack.css` and `slots/egg.<name>.html`; what it may declare (events, egg conditions and their parameters, limits) is `web/packs/vocabulary.json`, which the hub validates by. It lives inside a theme package (without `id`, `name`, `author`: the theme's apply) or on its own as a `.lullpack` zip, stored in `<data_dir>/packs/<id>/`. The built-in packs (`default` and one per design) are static files of the UI (`/packs/<id>/pack.json`, `/packs/<id>/sounds/*.ogg` as `audio/ogg`, listed in `/packs/index.json`), never listed here; a built-in pack id in a path is a 404.

| Method + path | Returns |
|---|---|
| `GET /api/packs` | `{ packs: [{ id, name, author, description, source: pack\|theme, theme, rev, sounds, eggs, css, slots }] }`: the listener's packs, then each stored theme's that carries one (`source: theme`, `theme` its id, `id` the theme's too, its name and author; `description` the pack's, else the theme's). `sounds`: event -> a URL, a list of URLs (taken in turn), `{ url, loop: true }` or `null` (silent on purpose). `eggs`: as declared, with `sound` a URL or `{ url, loop: true }`. `css`: `pack.css`'s URL or `null`. `slots`: the egg names with a `slots/egg.<name>.html`. URLs are `/api/packs/{id}/...` or `/api/themes/{id}/...`; `rev` (16 hex) changes with any of the files. A folder whose `pack.json` no longer reads is left out and logged |
| `GET /api/packs/{id}/{path}` | A file of a stored pack, ETag'd, `no-cache` (`.ogg` as `audio/ogg`) |
| `POST /api/packs[?replace=true]` (body: a `.lullpack`, up to 16 MB) | 200 the pack as listed, stored under the id its `pack.json` names. 409 when that id exists, unless `replace` |
| `PUT /api/packs/{id}` (body: a `.lullpack`) or `PUT /api/packs/{id}/{path}` (one file: a replaced sound, the listener's own pack) | 200 the pack as listed. A new pack starts with its `pack.json`. Every write is checked as the whole pack it makes: 400 names the file and what's wrong (below) |
| `DELETE /api/packs/{id}` | 204 |
| `GET /api/packs/{id}.lullpack` | The pack as a zip, for sharing |

A pack is refused (400, the message names the file and lists what is allowed) for: a field, event, condition, condition parameter or `once` lull doesn't know; a value out of its range (times `HH:MM[:SS]` or `24:00`, dates `MM-DD`, words of 1-40 letters, marks or digits in any script with `'` or `-`); a loop on any event but `buffering`, or on an egg's sound unless it plays `instead` of the buffering loop (a `player` condition); a `line` with a `{{...}}` other than `{{count}}` and `{{word}}`; a `go` that isn't `#/...`; a file that isn't Ogg Opus or Vorbis (read from its pages, not its name), a sound nothing names or a named one missing; a sound over 128 KB or sounds over 1 MB in all; a sound longer than its use allows (read from the last Ogg granule: 2 s for an event, 6 s for `boot` and an egg's sound, 20 s for the buffering loop or an egg's loop); `pack.css` or an egg slot breaking a theme's rules (themes.md section 8), or a slot for an egg the pack doesn't declare. A stored pack's files changing, by these endpoints or on disk, publishes `pack.changed` within a second.

## Subsonic (`crates/subsonic`)
